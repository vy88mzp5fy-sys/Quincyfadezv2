# QuincyFadez Mobile App

Official QuincyFadez iOS and Android app, built with Expo and React Native.

## Current build

- Premium black, gold and white QuincyFadez visual system
- Native Home, Services, Booking, Gallery, Reviews and Account screens
- Five-item mobile navigation: Home, Book, Gallery, Reviews and Account
- Native QuincyFadez booking flow with service, date and live time-slot selection
- Service-specific pricing and appointment durations
- Secure Stripe payment-method verification before appointment confirmation
- Stripe Payment Method Settings Sheet in Account
- QuincyFadez-owned appointment storage and booking history
- Upcoming bookings and cancellation support in Account
- Live availability generated from QuincyFadez working hours, blocked periods and existing bookings
- Booking window and minimum-notice controls
- Database protection against exact-slot double booking
- Google reviews, WhatsApp, directions and website shortcuts
- Branded app icon and splash screen
- Expo/EAS preview and production build profiles
- iOS and Android identifiers reserved as `com.quincyfadez.app`

## Native booking architecture

The QuincyFadez app is the primary booking system. Customers do not need to leave the app to choose an appointment.

Booking flow:

1. Choose a QuincyFadez service.
2. Choose an available date.
3. Choose a live QuincyFadez time slot.
4. Verify or use a saved payment method securely through Stripe.
5. Confirm the appointment inside QuincyFadez.
6. View the confirmed booking from Account.

Availability is generated by the backend from:

- configured weekly working hours
- service duration
- slot interval
- minimum booking notice
- future booking window
- blocked periods / time off
- confirmed or pending appointments

Working hours are intentionally closed by default until a real schedule is configured. The app must never invent availability.

## Payment architecture

The mobile app never receives or stores a customer's full card number or CVC. Stripe's native SDK collects payment details. The QuincyFadez backend stores only Stripe references and safe display metadata such as card brand and last four digits.

Account flow:

1. Open Account from the bottom navigation or home screen.
2. View upcoming and previous QuincyFadez bookings.
3. View saved-card status.
4. Open Stripe's Payment Method Settings Sheet to add or remove cards.
5. Removing the final attached card automatically requires verification before another protected booking can be confirmed.

## Reliability priorities

The booking system is treated as core product infrastructure, not a link-out feature. Before release it should cover:

- robust double-booking protection, including overlapping service durations
- rescheduling without creating temporary duplicate appointments
- configurable cancellation and reschedule rules
- customer contact details attached to bookings
- barber/admin schedule controls for working hours, breaks, holidays and blocked time
- clear recovery when a slot is taken while the customer is confirming
- confirmation, reminder and rebooking notifications

## Environment configuration

Mobile environment values:

- `EXPO_PUBLIC_API_URL` — deployed QuincyFadez backend URL
- `EXPO_PUBLIC_STRIPE_PUBLISHABLE_KEY` — optional client-side fallback; the app can also fetch the publishable key from the backend

Backend environment values:

- `STRIPE_SECRET_KEY` — Stripe server secret key only
- `STRIPE_PUBLISHABLE_KEY` — key returned to the mobile app through `/api/payments/config`
- Existing MongoDB environment values used by the backend

Never place a Stripe secret key in the mobile app or commit it to the repository.

## Development

This project targets Expo SDK 57 and lives separately from the production website in `/mobile`.

```bash
cd mobile
npm install
npx expo start
```

## Build commands

```bash
npm run build:ios
npm run build:android
npm run build:preview
```
